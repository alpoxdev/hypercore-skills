# Native Platform and Security

## Project mode

Identify whether native projects are generated by CNG/prebuild, intentionally committed and maintained, or absent. Config plugins/app config are the source of truth only where project ownership says so. Never overwrite manual native changes with a clean prebuild without explicit authorization and a reviewed diff/backup strategy.

## App configuration

Keep `app.config.ts`, `app.json`, `eas.json`, Metro, and TypeScript config at the app root unless existing workspace rules differ. Inspect resolved public config with `npx expo config`; do not print secret evaluation paths. Config-plugin or permission changes generally require a new native build, not only a JavaScript reload/update.

## Permissions

Treat permissions as two-part contracts: build-time native declaration/purpose text and runtime request/denial handling. Request at the point of user intent, explain purpose, support denied/blocked states, and test fresh-install flows. Minimize Android permissions and iOS usage descriptions. Expo Go is not evidence that standalone permission configuration is correct.

## Storage and secrets

Use `expo-secure-store` or an evidenced equivalent for small sensitive values through an adapter. Handle unavailable authentication, device changes, native errors, and data loss. Use non-secure storage only for non-sensitive data and define serialization/version migration. Never place secrets in `EXPO_PUBLIC_*`, `extra`, source, logs, analytics, or error reports.

## Platform seams

Prefer shared behavior with explicit adapters. Use `.ios.ts(x)` / `.android.ts(x)` when implementation truly differs; use `Platform.select` for small presentational differences, not large hidden business branches. Keep native-module calls behind typed modules so tests and unsupported platforms have explicit behavior.

## Dependencies and native effects

Use the installed Expo SDK compatibility path and inspect package support for the applicable React Native architecture. Package installs, pod/Gradle changes, `prebuild`, EAS credentials/build/update/submit, signing, push credentials, and store actions are gated side effects. When required capability or authorization is unavailable, provide the exact blocked check/change without claiming it ran.
