## Claims Used by This Skill

1. **Static frontend packaging.** Tauri integrates a separately built frontend and bundles its configured distribution. Therefore a Vite SPA must emit static assets to the configured distribution directory; the project must test the real production handoff, not only a development URL. Sources: [Frontend integration](https://v2.tauri.app/start/frontend/), [Vite guide](https://v2.tauri.app/start/frontend/vite/), [Configuration](https://v2.tauri.app/reference/config/).
2. **Native RPC boundary.** Tauri commands are registered Rust functions called from the frontend through `invoke`; they can be asynchronous and return values/errors. Keep raw invocation behind a narrow typed desktop API and validate/authorize every privileged command in Rust. Sources: [Calling Rust](https://v2.tauri.app/develop/calling-rust/), [Security overview](https://v2.tauri.app/security/).
3. **State belongs on the Rust side when it is native/application state.** Managed state is available to commands, but synchronization, persistence, and access policy are application responsibilities. Source: [Rust state](https://v2.tauri.app/develop/state-management/).
4. **Least privilege is configuration plus enforcement.** Capabilities and permissions constrain command/plugin access and can apply to selected windows/webviews or remote URLs. Scopes and CSP reduce exposure but do not turn client code into authorization. Sources: [Capabilities](https://v2.tauri.app/security/capabilities/), [Permissions](https://v2.tauri.app/security/permissions/), [CSP](https://v2.tauri.app/security/csp/).
5. **Choose IPC by semantics.** Use commands for request/response, events for small one-way notifications, and channels for ordered or high-throughput streams. React listeners survive SPA navigation and must be removed during effect cleanup. Sources: [IPC model](https://v2.tauri.app/concept/inter-process-communication/), [Calling frontend](https://v2.tauri.app/develop/calling-frontend/).
6. **Custom commands need an ACL path.** Registering a command does not by itself make it least-privilege. Declare application commands, map them through permissions/capabilities, and enforce scopes plus domain authorization in Rust. Sources: [Application manifest](https://v2.tauri.app/security/capabilities/#application-manifest), [Runtime authority](https://v2.tauri.app/security/runtime-authority/), [Command scopes](https://v2.tauri.app/security/scope/).
7. **Native and packaging behavior need native evidence.** Tauri documents tests across layers; unit/mocked frontend tests cannot by themselves prove a packaged webview, OS integration, or rejected privileged operation. Sources: [Testing](https://v2.tauri.app/develop/tests/), [Mocking](https://v2.tauri.app/develop/tests/mocking/), [WebDriver](https://v2.tauri.app/develop/tests/webdriver/).

## Application Caveats

- Registry observations are a snapshot, not version pins or a compatibility guarantee. Use the target lockfile and installed package metadata for implementation decisions.
- Official pages describe product mechanisms, not authority to access files, credentials, signing keys, production services, or publish/release an app. Those actions require explicit user authority.
- Preserve the source URL and `last_verified_at` when citing a claim. Replace stale claims rather than blending old and new vendor behavior.
